# v6.7.6 老用例失败排查与修改指南

## 概述

v6.7.6 是一个**契约对齐版本**——框架实现现在严格遵循 `CORE_DESIGN_CONSTRAINTS.md` 中声明的所有约束。

**核心变化：** 以前静默通过的无效用例，现在会以明确的错误信息失败。

这意味着：
- 框架行为没有 bug，是老用例写法不符合契约
- 错误信息会精确指出违反了哪条约束
- 修改后的用例在所有 v6.x 版本上都能正确运行

## 失败类型详解

### 1. 旧 model 简化定位器格式被拒绝

**症状：**
```
ModelParseError: 使用了已废弃的定位器格式
```

**原因：** v5.4.0 起只支持 `<location type="...">值</location>` 格式，旧的属性式定位器不再解析。

**检查命令：**
```bash
grep -rn 'value=\|locator=' model/*.xml
```

**修改方式：** 将属性式定位器改为子元素式。

**修改前：**
```xml
<element name="btn" type="id" value="submitBtn"/>
```

**修改后：**
```xml
<element name="btn"><location type="id">submitBtn</location></element>
```

---

### 2. data.xml / data_verify.xml 不再作为运行时数据源

**症状：**
```
RuntimeError: data.xml 已废弃，请迁移至 data.sqlite
```

**原因：** v6.0+ 统一使用 data.sqlite 作为测试数据源，XML 数据文件不再被运行时加载。

**检查命令：**
```bash
# 检查是否存在废弃的 XML 数据文件（globalvalue.xml 除外）
ls data/*.xml | grep -v globalvalue.xml
```

**修改方式：** 使用 CLI 工具将 XML 数据导入 SQLite。

```bash
rodski data import <module> --overwrite
```

---

### 3. SQLite 同表行缺字段失败

**症状：**
```
DataSchemaError: 表 'xxx' 行 'yyy' 缺少字段 missing=[field_a, field_b]
```

**原因：** 所有行必须包含 schema 声明的全部字段。不允许某些行有字段、某些行没有。

**检查命令：**
```bash
rodski data validate <module> --strict
```

**修改方式：** 补齐缺失字段，根据业务含义填入以下占位值之一：

| 占位值 | 含义 |
|--------|------|
| `BLANK` | 空字符串，执行时传入 "" |
| `NULL` | 不传该参数 |
| `NONE` | 跳过该步骤对应操作 |

---

### 4. type/verify 缺字段不再静默跳过

**症状：**
```
InvalidParameterError: 模型元素 'xxx' 在数据行 'yyy' 中缺少对应字段
```

**原因：** 旧版本中，如果数据行缺少模型元素对应的字段，会静默跳过该元素的操作。v6.7.6 要求显式声明跳过意图。

**检查命令：**
```bash
rodski data validate <module> --strict
```

**修改方式：** 在 data.sqlite 对应表中补齐字段，值填 `BLANK`（表示显式跳过该元素操作）。

---

### 5. 接口/DB _verify 使用 ${Return[-1]} 被拒绝

**症状：**
```
InvalidParameterError: 接口/DB verify 的实际值已自动从 Return[-1] 读取，期望值不能再引用 Return[-1]
```

**原因：** `_verify` 表中的字段值是**期望值**，框架会自动从 `Return[-1]` 读取**实际值**进行比较。如果期望值也写 `${Return[-1]}`，则期望值=实际值，断言永远通过，无实际校验意义。

**检查命令：**
```bash
# 在 data.sqlite 中搜索 _verify 表是否包含 ${Return[-1]}
sqlite3 data/data.sqlite "SELECT name FROM sqlite_master WHERE type='table' AND name LIKE '%_verify';" | \
  xargs -I{} sqlite3 data/data.sqlite "SELECT '{}', * FROM {} WHERE 1" | \
  grep 'Return\[-1\]'
```

**修改前：**
```
field_value = ${Return[-1].token}
```

**修改后：**
```
field_value = expected_literal_value
```

将 `${Return[-1].xxx}` 替换为实际期望的字面量值（如 `"success"`、`200`、`true` 等）。

---

### 6. DB verify 不能空校验通过

**症状：**
```
AssertionFailedError: 比较字段数为 0，无有效断言
```

**原因：** database model 中无普通 element（只有 `__` 前缀的内部字段），旧逻辑会跳过所有字段导致空校验通过。v6.7.6 要求至少有一个有效比较字段。

**检查命令：**
```bash
# 检查 _verify 数据行是否有非 __ 前缀的字段
rodski data validate <module> --strict
```

**修改方式：** 确保 `_verify` 数据行中有至少一个非 `__*` 前缀的字段用于实际比较。

---

### 7. Case XML data 中 ${random(...)} / ${date(...)} 被拒绝

**症状：**
```
ValueError: 内置函数只能写在 data.sqlite 字段值中，不能写在 Case XML 的 data 属性中
```

**原因：** Case XML 的 `data` 属性只做数据行引用，不解析内置函数表达式。内置函数必须写在 data.sqlite 的字段值中。

**修改前：**
```xml
<test_step action="send" model="API" data="${random(int, 4)}"/>
```

**修改后：**
```xml
<test_step action="send" model="API" data="R001"/>
```

然后在 data.sqlite 对应表的 `R001` 行中，将需要随机值的字段设为 `${random(int, 4)}`。

---

### 8. run 路径规范化

**症状：**
```
FileNotFoundError: 脚本文件不存在: <resolved_path>
```

**原因：** `fun/` 前缀的路径规范化逻辑变更，框架现在统一解析脚本路径。

**检查命令：**
```bash
# 确认脚本文件在解析后的路径确实存在
ls fun/<script_name>.py
```

**修改方式：** 确认脚本文件存在于正确位置。`data="fun/script.py"` 和 `data="script.py"` 现在都能正确解析（框架会自动补全 `fun/` 前缀）。如果文件确实不存在，将脚本放到 `fun/` 目录下。

---

### 9. wheel/sdist 安装态缺依赖或缺 schemas/*.xsd

**症状：**
```
ImportError: No module named 'xxx'
```
或
```
FileNotFoundError: schemas/xxx.xsd 不存在
```

**原因：** 旧版本包构建配置不完整，导致安装后缺少运行时依赖或 schema 文件。

**检查命令：**
```bash
pip show rodski
python -c "import rodski; print(rodski.__version__)"
```

**修改方式：** 升级到 v6.7.6 或更高版本。

```bash
pip install --upgrade rodski>=6.7.6
```

## AI Agent 固定检查顺序

当老用例在 v6.7.6 上失败时，AI Agent 应按以下固定顺序排查：

```
1. rodski run <case> --dry-run          # 获取完整错误信息
2. 检查 model/model.xml 定位器格式       # 对应失败类型 1
3. 检查 data/ 下是否有废弃 XML 数据文件   # 对应失败类型 2
4. rodski data validate <module> --strict # 对应失败类型 3、4、6
5. 检查 _verify 表是否包含 ${Return[-1]} # 对应失败类型 5
6. 检查安装态 schemas/*.xsd 和依赖       # 对应失败类型 9
```

**排查原则：**
- 先运行 `--dry-run` 获取错误信息，根据错误类型直接定位到对应章节
- 如果错误信息不明确，按上述顺序逐项检查
- 类型 1-8 修改用例即可，类型 9 需要升级框架包

## 判断标准表

| 失败类型 | 错误关键字 | 处置方式 |
|---------|-----------|---------|
| 1. 旧定位器格式 | `ModelParseError` | 修改老用例 |
| 2. XML 数据文件 | `data.xml 已废弃` | 修改老用例 |
| 3. SQLite 缺字段 | `DataSchemaError` | 修改老用例 |
| 4. 缺字段静默跳过 | `InvalidParameterError` + `缺少对应字段` | 修改老用例 |
| 5. Return[-1] 滥用 | `InvalidParameterError` + `Return[-1]` | 修改老用例 |
| 6. 空校验 | `AssertionFailedError` + `比较字段数为 0` | 修改老用例 |
| 7. XML 内置函数 | `ValueError` + `内置函数` | 修改老用例 |
| 8. run 路径 | `FileNotFoundError` + 脚本路径 | 修改老用例 |
| 9. 安装缺失 | `ImportError` / `FileNotFoundError` + `.xsd` | 升级/重装 RodSki 包 |

## 快速修复流程图

```
老用例失败
  │
  ├─ 错误信息包含 ModelParseError？
  │    └─ 是 → 修改 model XML 定位器格式（类型 1）
  │
  ├─ 错误信息包含 data.xml 已废弃？
  │    └─ 是 → 执行 rodski data import（类型 2）
  │
  ├─ 错误信息包含 DataSchemaError？
  │    └─ 是 → 补齐 SQLite 缺失字段（类型 3）
  │
  ├─ 错误信息包含 缺少对应字段？
  │    └─ 是 → 补齐字段填 BLANK（类型 4）
  │
  ├─ 错误信息包含 Return[-1]？
  │    └─ 是 → 替换为字面量期望值（类型 5）
  │
  ├─ 错误信息包含 比较字段数为 0？
  │    └─ 是 → 添加有效比较字段（类型 6）
  │
  ├─ 错误信息包含 内置函数？
  │    └─ 是 → 将函数移到 SQLite 字段值中（类型 7）
  │
  ├─ 错误信息包含 FileNotFoundError + 脚本？
  │    └─ 是 → 确认脚本路径正确（类型 8）
  │
  └─ 错误信息包含 ImportError 或 .xsd？
       └─ 是 → pip install --upgrade rodski>=6.7.6（类型 9）
```
