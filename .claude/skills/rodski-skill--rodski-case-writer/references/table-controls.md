# RodSki 表格与复杂控件

表格、Handsontable、弹窗表单、下拉框、富文本、树选择器和其他复杂 Web 控件使用本文。实时契约仍以 `TEST_CASE_WRITING_GUIDE.md` 为准。

## 表格

- 表格操作应锚定业务行和目标列，不要锚定宽泛页面文本。
- 对重复 DOM 行，应限定到第一个匹配业务行；只有证明 DOM 重复且稳定后，才有意添加 `[1]`。
- 删除动作应找到实际包含可见删除控件的第一行；不要假设 `tr[1]` 可删除。
- 列表验证应断言体现业务结果的行/列值，而不是任意页面文本。

## Handsontable

- 编辑前定位第一个空行或目标业务行。不要假设页面加载时 `.current` 已存在。
- 使用 `click` 选择单元格，然后用 `key_press【Enter】` 或页面特定激活路径进入编辑模式。
- 输入触发 lookup/fillback 后，使用 `key_press【Tab】` 或真实 blur/search 触发，再验证填充结果。
- 对 iframe/table 混合控件，优先使用稳定 frame 加行/列定位器；除非证明必要，否则避免脆弱的双击 hack。

## 弹窗与对话框控件

- 弹窗定位器应限定在当前可见的 `.br-modal`、`.br-modal__container` 或 `[role=dialog]` 内。
- 当存在重复按钮时，“确定”和“保存”等按钮必须限定到活动弹窗 footer。
- 对嵌套弹窗，先保存/确认内层弹窗，等待其关闭，再保存/确认外层弹窗。
- 负向流程应断言真实阻止状态：toast、按钮禁用、弹窗仍打开、字段错误，或校验文本。

## 下拉框与选择器

- 将下拉交互拆成打开控件和从当前可见下拉面板选择。
- 优先使用可见选项文本加非禁用条件，再考虑深层内部 span 结构。
- 隐藏的 `<select>` 或隐藏 radio/checkbox input 通常是锚点，不是点击目标；应点击可见父节点/label。
- 对树选择器，锚定当前面板和目标标签，然后验证已选 chip 或汇总文本。

## 富文本与编辑器

- 富文本编辑器通常需要同步 iframe body、隐藏 textarea、编辑器实例和 change/input 事件。
- 当 `type` 无法提交真实内容时，使用小而受控的 `evaluate` 做编辑器同步。
- 编辑器同步后，通过常规 RodSki `verify` 验证页面状态或保存结果。
- 不要为了让表单保存而删除必填富文本输入。

## 数据行

- 将原子动作放入数据字段值：`click`、`select【值】`、`key_press【Tab】`、`scroll【0,500】`。
- 动作参数使用中文括号。
- 数据字段名与模型元素名保持完全对齐。
- 对复杂控件，每个交互阶段使用一条命名清楚的数据行，比许多单击 case 步骤更容易修复。
