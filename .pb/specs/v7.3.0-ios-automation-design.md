## 1. 背景与目标

### 1.1 现状

RodSki 已有 iOS 的**骨架代码**，但从未真正落地：

| 已有 | 缺失 |
|------|------|
| `drivers/ios_driver.py`（仅 `__init__` + `shake()`）| iOS 手势（scroll/swipe/long_press）|
| `driver_factory._create_ios_driver()` | iOS 按键映射 |
| `app://ios/{bundleId}` URI 定义 | iOS demo 用例 / model |
| CORE_DESIGN_CONSTRAINTS 中 iOS 已列入支持平台 | 真机验收（从未跑通）|

### 1.2 目标

| 目标 | 说明 |
|------|------|
| **用例跨平台兼容** | 同一条 case XML 能同时跑 Android 和 iOS，只换 model 或 plan |
| **定位器智能复用** | 跨平台定位器（ocr/text/vision_image）一处编写两端复用；平台专属定位器（id/xpath）在 model 中标记区分 |
| **IOSDriver 能力对齐** | 补全 scroll/swipe/key_press/start_app 等 Android 已有的方法 |
| **真机可验收** | 提供最小 iOS Demo App + WDA 环境文档，跑通一条完整 case |
| **不新增关键字** | 完全复用 navigate/type/verify/wait/close，与 Android 一致 |

## 2. 核心设计原则

### 2.1 关键字层：完全平台无关

`type` / `verify` / `navigate` / `wait` / `close` 在 iOS 上语义与 Android 完全一致。
case XML 的 `action` 不区分平台——这是 RodSki "关键字统一" 原则的延续。

```xml
<!-- 这条 test_step 在 Android 和 iOS 上完全相同 -->
<test_step action="type" model="LoginScreen" data="L001"/>
```

### 2.2 模型层：平台差异的唯一承载点

平台差异**只允许出现在 model.xml 中**，通过两种机制承载：

1. **`driver_type` 属性**：标记该 model 属于哪个平台（`android` / `ios`）
2. **定位器优先级与类型**：平台专属定位器（id/xpath）标记平台，跨平台定位器（ocr/text/vision_image）共享

### 2.3 数据层：完全复用

`data.sqlite` 中的测试数据（用户名、密码、断言期望值）与平台无关，Android 和 iOS 共用同一份数据。

### 2.4 定位器复用优先级（本设计核心）

```
跨平台定位器（一次编写，两端复用）
  ├── ocr          文字识别       —— 两端完全相同
  ├── text         文本匹配       —— 两端语义相同（XPath 构造不同，driver 内部处理）
  ├── vision_image 图片模板匹配   —— 两端完全相同（OpenCV，与平台无关）
  ├── vision       语义定位       —— 两端完全相同（VLM/Accessibility Tree）
  └── vision_bbox  坐标定位       —— 两端相同（注意分辨率差异）

平台专属定位器（必须在 model 中标记区分）
  ├── id     Android: com.x:id/btn    iOS: accessibility-id 或 name
  └── xpath  Android: //*[@text=..]   iOS: //XCUIElementType.. 结构不同
```

**设计判断**：
- 如果一个元素能用 ocr/text/vision_image 定位 → **两端共用一个 model 定义**
- 如果必须用 id/xpath（性能或精度要求）→ **两端各写一份 model，或在同一元素下用平台条件标记**

## 3. Android / iOS 差异分析

| 维度 | Android (UiAutomator2) | iOS (XCUITest) | RodSki 处理 |
|------|----------------------|----------------|------------|
| 元素 id | resource-id `com.x:id/btn` | accessibility-id / name | model 中 `driver_type` 区分 |
| 文本定位 | `//*[@text='登录']` | `//*[@label='登录' or @name='登录']` | driver 内部 `_resolve_locator` 按平台构造 |
| class | `android.widget.Button` | `XCUIElementTypeButton` | model 中区分 |
| 滚动 | swipe 坐标 | `mobile: scroll` direction | driver 内部封装 |
| 按键 | `pressKeyCode(keycode)` | 无 keycode，用 `mobile: pressButton` 或坐标 | driver 内部映射 |
| App 启动 | `appPackage` + `appActivity` | `bundleId` | URI 格式区分 |
| App 切换 | `activate_app(package)` | `activate_app(bundleId)` | 接口一致 |
| 真机连接 | ADB（免签名）| WebDriverAgent（需开发者签名）| 文档说明 |
| 录像 | `startRecordingScreen` | `mobile: startRecordingScreen`（mp4）| 已有 recording_backend |
| Accessibility Tree | `text`/`content-desc`/`resource-id` | `label`/`value`/`name`/`type` | 已兼容（appium_driver 读多属性）|

**关键发现**：`appium_driver.py` 的 `get_element_text_by_locator()` 已经按 `["text","value","label","name","content-desc"]` 优先级读属性，**文本读取已经是跨平台的**。`get_accessibility_tree()` 也已同时读 Android 和 iOS 的属性。所以 **verify 关键字在 iOS 上无需改动**。

## 4. 定位器兼容设计（核心）

### 4.1 三种兼容模式

#### 模式 A：完全复用（跨平台定位器）

元素用 ocr/text/vision_image 定位时，**一个 model 定义同时服务两端**：

```xml
<!-- 这个 model 既可用于 Android 也可用于 iOS，driver_type 设为 mobile 表示通用 -->
<model name="LoginScreen" type="ui" driver_type="mobile">
  <element name="loginBtn" type="mobile">
    <type>button</type>
    <location type="ocr">登录</location>          <!-- 两端通用 -->
    <location type="vision_image">../assets/login_btn.png</location>  <!-- 两端通用 -->
  </element>
</model>
```

> 新增 `driver_type="mobile"` 作为"平台无关移动端"标记，运行时由 CLI/plan 注入实际平台。

#### 模式 B：平台专属（id/xpath 区别）

元素必须用平台专属 id 时，在同一 `<location>` 上用 `platform` 属性标记：

```xml
<model name="LoginScreen" type="ui" driver_type="mobile">
  <element name="username" type="mobile">
    <type>input</type>
    <!-- 平台专属 id：用 platform 属性区分，运行时按当前平台选择 -->
    <location type="id" platform="android" priority="1">com.rodski.demo:id/username</location>
    <location type="id" platform="ios"     priority="1">username_field</location>
    <!-- 跨平台兜底：两端都能用 -->
    <location type="ocr" priority="2">用户名</location>
  </element>
</model>
```

**解析规则**：
- 运行时已知当前平台（android/ios）
- 同 `priority` 下，优先选 `platform` 匹配当前平台的 location
- `platform` 缺省 = 通用（两端都适用）
- 当前平台无匹配的专属 location 时，降级到通用 location（ocr/text/vision_image）

#### 模式 C：双 model（差异过大时）

如果 Android 和 iOS 的页面结构差异太大（元素层级/数量不同），允许写两个 model：

```
model/
├── model_android.xml   driver_type="android"
└── model_ios.xml       driver_type="ios"
```

plan 通过参数指定加载哪个 model。这是最后手段，优先用模式 A/B。

### 4.2 定位器复用决策表

| 定位器 | 是否跨平台 | model 写法 |
|--------|-----------|-----------|
| `vision_image` | ✅ 完全跨平台 | 一份，无 platform 属性 |
| `ocr` | ✅ 完全跨平台 | 一份，无 platform 属性 |
| `vision` | ✅ 完全跨平台 | 一份，无 platform 属性 |
| `vision_bbox` | ⚠️ 坐标可能因分辨率不同 | 可分别标 platform（不同坐标）|
| `text` | ✅ 语义跨平台（driver 内部构造不同 XPath）| 一份，无 platform 属性 |
| `id` | ❌ 平台专属 | 两端各一份，标 platform |
| `xpath` | ❌ 平台专属（XCUI 结构不同）| 两端各一份，标 platform |
| `class` | ❌ 平台专属 | 两端各一份，标 platform |

### 4.3 XSD 扩展

`model.xsd` 的 `location` 元素新增可选 `platform` 属性：

```xml
<xs:attribute name="platform" use="optional">
  <xs:simpleType>
    <xs:restriction base="xs:string">
      <xs:enumeration value="android"/>
      <xs:enumeration value="ios"/>
      <!-- 缺省表示通用（两端适用）-->
    </xs:restriction>
  </xs:simpleType>
</xs:attribute>
```

`model` 的 `driver_type` 枚举新增 `mobile`（平台无关移动端标记）：

```
driver_type: web | interface | database | windows | macos | android | ios | mobile
```

## 5. 模型 XML 设计

### 5.1 推荐写法（模式 A + B 混合）

```xml
<?xml version="1.0" encoding="UTF-8"?>
<models>
  <!-- driver_type=mobile 表示平台无关，运行时注入实际平台 -->
  <model name="LoginScreen" type="ui" driver_type="mobile">

    <!-- 用户名：id 平台专属 + ocr 兜底 -->
    <element name="username" type="mobile">
      <type>input</type>
      <location type="id" platform="android" priority="1">com.rodski.demo:id/username</location>
      <location type="id" platform="ios"     priority="1">username_field</location>
      <location type="ocr"                   priority="2">用户名</location>
      <desc>用户名输入框</desc>
    </element>

    <!-- 登录按钮：纯跨平台定位器，无需 platform 标记 -->
    <element name="loginBtn" type="mobile">
      <type>button</type>
      <location type="text" priority="1">登录</location>
      <location type="ocr"  priority="2">登录</location>
      <location type="vision_image" priority="3">../assets/login_btn.png</location>
      <desc>登录按钮（两端共用，无平台差异）</desc>
    </element>

  </model>
</models>
```

### 5.2 ModelParser 改动

`model_parser.py` 解析 `<location>` 时读取 `platform` 属性，运行时按当前 `driver_type` 过滤：

```python
def select_locations(element, current_platform):
    """按当前平台过滤 location 列表。

    规则：
    - platform 匹配当前平台 → 保留
    - platform 缺省（通用）→ 保留
    - platform 不匹配 → 跳过
    然后按 priority 排序。
    """
    selected = []
    for loc in element.locations:
        plat = loc.get("platform")
        if plat is None or plat == current_platform:
            selected.append(loc)
    return sorted(selected, key=lambda l: l.get("priority", 999))
```

## 6. 用例兼容设计

### 6.1 同一 case 跑两端

case XML **完全不需要改动**。同一条 `login.xml` 既可跑 Android 也可跑 iOS：

```xml
<cases>
  <case execute="是" id="APP001" title="登录成功" component_type="界面">
    <pre_process>
      <test_step action="navigate" model="" data="${GlobalValue.DefaultValue.AppURI}"/>
    </pre_process>
    <test_case>
      <test_step action="type"   model="LoginScreen" data="L001"/>
      <test_step action="verify" model="HomeScreen"  data="V001"/>
    </test_case>
    <post_process>
      <test_step action="close" model="" data=""/>
    </post_process>
  </case>
</cases>
```

### 6.2 平台切换方式

平台差异通过 **globalvalue.xml + plan** 控制，case 不动：

```xml
<!-- data/globalvalue_android.xml -->
<globalvalue>
  <group name="DefaultValue">
    <var name="AppURI" value="app://android/com.rodski.demo/.LoginActivity"/>
    <var name="Platform" value="android"/>
  </group>
</globalvalue>

<!-- data/globalvalue_ios.xml -->
<globalvalue>
  <group name="DefaultValue">
    <var name="AppURI" value="app://ios/com.rodski.demo"/>
    <var name="Platform" value="ios"/>
  </group>
</globalvalue>
```

## 7. IOSDriver 能力补全

`IOSDriver` 当前只有 `shake()`，需补全与 Android 对齐的方法（大部分继承自 AppiumDriver，iOS 特有的需重写）：

| 方法 | Android 实现 | iOS 需补全 |
|------|-------------|-----------|
| `_resolve_locator` (text) | `//*[@text='值']` | `//*[@label='值' or @name='值']` |
| `_resolve_locator` (id) | resource-id | accessibility-id（AppiumBy.ACCESSIBILITY_ID）|
| `scroll` | swipe 坐标 | `mobile: scroll` {direction} |
| `swipe` | W3C actions | `mobile: swipe` |
| `key_press` | `pressKeyCode` | `mobile: pressButton`（home/volumeup）或 `keys()` |
| `long_press` | W3C actions | `mobile: touchAndHold` |
| `start_app` | adb am start | `activate_app(bundleId)` |
| `hide_keyboard` | `hide_keyboard()` | `hide_keyboard()`（iOS 需点 return）|

### 7.1 `_resolve_locator` 平台分发

`AppiumDriver._resolve_locator` 当前是 Android 专属（text → `@text`）。改造为平台感知：

```python
# AppiumDriver 基类提供钩子，子类重写
def _resolve_locator(self, locator_type, locator_value):
    lt = locator_type.lower()
    if lt == "text":
        return AppiumBy.XPATH, self._text_xpath(locator_value)
    ...

# AndroidDriver
def _text_xpath(self, value):
    return f"//*[@text='{value}']"

# IOSDriver
def _text_xpath(self, value):
    return f"//*[@label='{value}' or @name='{value}' or @value='{value}']"
```

### 7.2 iOS id 定位

iOS 的 `id` 语义是 accessibility-id：

```python
# IOSDriver 重写 id 映射
_LOCATOR_MAP_IOS = {
    "id":    AppiumBy.ACCESSIBILITY_ID,   # iOS: accessibility-id
    "name":  AppiumBy.NAME,
    "class": AppiumBy.CLASS_NAME,         # XCUIElementType...
    "xpath": AppiumBy.XPATH,
    "predicate":   AppiumBy.IOS_PREDICATE,    # iOS 特有
    "class_chain": AppiumBy.IOS_CLASS_CHAIN,  # iOS 特有，高性能
}
```

> iOS 新增两个 iOS 专属定位器类型 `predicate` / `class_chain`，作为高性能选项（仅 iOS 可用，标 `platform="ios"`）。

## 8. App 启动与 navigate

`navigate` 关键字解析 `app://` URI（已有逻辑，需验证 iOS 路径）：

```
app://android/{package}/{activity}   → AndroidDriver
app://android/{package}              → AndroidDriver 默认 Activity
app://ios/{bundleId}                 → IOSDriver activate_app(bundleId)
```

iOS 启动流程：
1. `navigate` 检测 `app://ios/` 前缀
2. 通过 `driver_factory` 创建 `IOSDriver(bundle_id=...)`
3. XCUITest 自动启动 App（cap 里的 bundleId）
4. 已有实例则 `activate_app(bundleId)` 切换
